The attack

Both hops take a request target from an untrusted party and splice it onto a trusted origin to decide where to send a secret — but splicing is not a boundary. In the gate, new URL(path + search, claims.target) treats the ticket's target as a base that a protocol-relative path (//evil.example/x) simply discards, so the attacker names the host and the gate hands it that workspace's derived host secret; the ticket check only proves the ticket was signed and unexpired, and the hostname check reads url.hostname, never the path. In the tunnel client the same mistake wears a different dialect: the local URL was built by string concatenation, where a target beginning with @ turns http://127.0.0.1:38017 into userinfo and promotes evil.example to the host — and the frame carrying that path is JSON.parse'd straight from the relay dial-back socket and cast to HttpDialFrame with no validation at all, so a compromised, impersonated, or misresolved relay gets HOST_SERVICE_SECRET for the asking. Variants that defeat a naive prefix check: /\evil.example (backslash), and /<TAB>/evil.example or /<LF>/evil.example, which the URL parser strips back into protocol-relative after the check has already passed.

The fix

Both defects are the same mistake in two dialects, so the guard is one shared module — packages/shared/src/upstream-url.ts — with two entry points that cannot drift, because the second is built on the first:

  • isOriginFormTarget(target) — the syntactic half, for a hop that forwards a target on without resolving it (the relay).
  • resolveUpstreamUrl(origin, target) — for a hop that resolves a target and then sends a secret to the result (gate, tunnel). Returns the URL only if it provably lands on origin; null otherwise.

It checks the target and re-checks the resolved origin, so it does not depend on which URL-construction style the caller used. Nothing is normalized or repaired: a target that tried to move the origin is refused, not corrected.

packages/shared/src/upstream-url.ts

/**
 * C0 controls, space and DEL. The URL parser strips tab, CR and LF *before*
 * resolving, so `/<tab>/evil.example` becomes protocol-relative after any
 * naive prefix check has already passed; none of them belong in a request
 * target regardless.
 */
function hasForbiddenCharacter(target: string): boolean {
	for (let i = 0; i < target.length; i++) {
		const code = target.charCodeAt(i);
		if (code <= 0x20 || code === 0x7f) return true;
	}
	return false;
}

export function isOriginFormTarget(requestTarget: string): boolean {
	if (!requestTarget.startsWith("/")) return false;
	if (requestTarget[1] === "/" || requestTarget[1] === "\\") return false;
	return !hasForbiddenCharacter(requestTarget);
}

export function resolveUpstreamUrl(
	origin: string,
	requestTarget: string,
): URL | null {
	let base: URL;
	try {
		base = new URL(origin);
	} catch {
		return null;
	}
	if (!isOriginFormTarget(requestTarget)) return null;

	let upstream: URL;
	try {
		upstream = new URL(requestTarget, base);
	} catch {
		return null;
	}
	// The checks above are what makes the refusal legible; this is what makes
	// it correct, and stays correct if URL parsing grows a new corner.
	if (upstream.origin !== base.origin) return null;
	if (upstream.username !== "" || upstream.password !== "") return null;
	return upstream;
}

Residual risk & what is not covered

Advisory bodies could not be read. gh api repos/superset-sh/superset/security-advisories/<id> returned 403 Resource not accessible by integration for both IDs — the token in this sandbox has no repository-advisory scope. Verification worked from the task brief plus the code. Anything the advisories assert that the brief does not restate is unverified here, so a reviewer with advisory access should sanity-check the fix against the full reports.

  • Cross-tenant reach is not established, and the fix does not depend on it. The gate derives the secret from the ticket's workspace, so what leaked was the attacker's own workspace host secret plus a full SSRF from the gate Worker — which is why this is Medium, not cross-tenant.
  • The relay remains a trusted hop for everything else. This fix stops it choosing the origin; it does not authenticate the relay or schema-validate the rest of the dial frames. HttpDialFrame is still a bare TypeScript interface, JSON.parse'd and cast — method and headers are still taken as given.
  • The pathAfterHost slice is still encoding-sensitive. apps/relay/src/index.ts:216 slices the raw pathname by the length of the decoded hostId, so percent-encoding in the host segment shifts the slice. I could not build a working exploit — a caller cannot choose an arbitrary hostId, it must pass authenticate(…, "reach") for a host they own — and the new guard now catches the shapes that mattered, but the slice itself is still worth tidying.
  • One pre-existing, unrelated test failure. health.check > serialises the current boot's stamps and the runtime in sandbox mode fails identically on the clean tree (verified by stashing every change). Left alone.
  • check:i18n not run — the change adds no user-facing strings; the two new messages are console.warn diagnostics, which are not translated.
