Design exploration · 25 September 2026

Moving a workspace between devices in one click

Click one thing on the laptop and the workspace — files, uncommitted changes, agent context, terminals, layout — is open and running on the desktop, in the cloud, or back down again. The mechanism: a handoff is a commit.

The shape of the problem

What a workspace actually is

Several kinds of state live under one row in the host's workspaces table, and they have nothing in common except the directory they share. Sorting them is most of the design, because they want completely different treatment.

Layer Where it lives Size Move it?
Committed history .git large, already replicated yes — both ends have ~all of it
Dirty state
worktree, index, untracked, stashes		 working tree KBs–MBs yes — this is the whole problem
Ignored-but-precious
.env, .envrc, local config		 working tree, gitignored KBs yes — nothing else reproduces it
Derived
node_modules, .venv, caches		 working tree, gitignored GBs no — reproduce, never ship
Session
agent context, scrollback, bindings, layout		 host SQLite, localStorage, harness store KBs already solved
Running processes kernel — no — restart beats migrate

The consequence worth noticing: everything worth moving is either already in a git object graph, or small enough to put into one. That is the entire design.

The mechanism

A handoff is a commit

Build a commit that captures the dirty state, push it to the other device, restore from it. Nothing more exotic — but doing it in git gets the hard parts free: content addressing, so a file unchanged since the last handoff never moves; delta compression; pack negotiation, so only objects the destination lacks cross the wire; atomicity, since a ref either exists or doesn't; and resumability.

Source side

# the dirty state, without touching the user's index or worktree
STASH=$(git stash create)
git stash export --to-ref refs/superset/handoff/<id>  # git 2.51+

git stash create writes a commit whose parents are HEAD, a commit of the index, and a commit of the untracked files — without mutating the worktree, the index, or refs/stash. Git 2.51 then added stash export/import, which turn the stash stack into a chain of commits transferable by the normal fetch and push mechanisms. Our wire format, shipped upstream last year.

Two things stash won't carry, added as extra trees in the same commit:

  • Ignored-but-precious files — an allowlist (.env*, .envrc, .dev.vars, plus a per-project list in .superset/config.json) hashed into a side tree. Without these the destination boots a workspace that can't talk to anything.
  • The manifest — workspace metadata, the terminal and binding list, scrollback tails, pane layout, and one handoff prompt per live agent session.

Transport, in preference order

  1. Device to device over the relay we already run

    apps/relay already multiplexes streams to a host's tunnel, and host-service already runs an authenticated HTTP server. Mount git's smart-HTTP protocol at /git/:workspaceId and the destination runs a plain git fetch. No third party, and auth and addressing are solved already.

  2. Park it

    The source can't stay awake — a closing lid is the normal case for "move to my desktop". A bundle built against the destination's own tips, or an encrypted blob it pulls when it wakes. Client-side encryption is not optional: the payload carries .env files and agent context.

  3. A hidden ref on origin

    Invisible in GitHub's branch UI, no PR, no pollution. Cheapest to build and works everywhere the project already pushes — but it puts uncommitted work and secrets on the user's forge, so opt-in per project, never the default.

The part I over-designed, then deleted

Moving the session: already built

The app already has session transfer, and it is device-independent by accident of good design. superset agents create --from-terminal reads a terminal's context, wraps it with buildTerminalSessionHandoffPrompt, and launches a fresh agent seeded with it. Every link in that chain is text. 

prompt = hostA.terminal.transcript({ workspaceId, terminalId })
         hostB.agents.run({ workspaceId: <new>, agent: <same>, prompt })

terminal.transcript returns a string; agents.run takes a string. No path, no file, no harness store anywhere in it. So a cross-device move doesn't copy transcripts — it calls the transfer it already has with two different clients. The only change: buildHandoffPromptFromTerminal currently uses one client for both halves. Split the read host from the launch host. Roughly ten lines, not a subsystem.

What that buys, all of it for free:

  • No transcript files move. Claude's path-encoding trap — the directory name encoding the absolute worktree path, the per-record cwd — leaves the critical path entirely.
  • Harness-agnostic. Claude, Codex, OpenCode and pi transfer identically, because the wire format is a prompt. You can land a Claude session onto Codex.
  • Version-proof. No dependency on both machines running the same harness build.
  • Works to and from a sandbox with no special casing.

The one real limit

Partly superseded — see the handoff note under "A working implementation". Keep this path as the fallback for a pane whose agent is dead or unresponsive.

Transfer is bounded at TERMINAL_HANDOFF_MAX_CHARS (36,000 chars, roughly 9–12k tokens), so continuity is summary-grade: the agent picks the work up, it does not possess turn 3 of 200. For moving between work sessions that is the right trade, and it is the trade the existing same-machine handoff already makes.

If people do ask for the exact session, the upgrade is additive: put the raw transcript in the handoff commit and restore it into the destination harness's store so --resume resolves. That is when the path-rewrite tax gets paid. Worth doing on evidence, not before.

Still needed on the session side

  • A moved value for terminal_agent_bindings.endReason, so the source's auto-resume doesn't relaunch an agent that now lives elsewhere. The existing values carry intent precisely and a move is a new intent.
  • A lineage_id on workspaces, so a moved workspace's PR link, task and tags follow it — workspaces.id is host-local.
  • Pane layout as a one-shot localStorage payload cleared by its consumer, per the persisted-key policy.

Someone built it · 29 September 2026

A working implementation to read

Fabien Penso shipped this feature the day before this revision: "Right-click a worktree, pick a remote host, and your branch, uncommitted changes, tabs and running agents move there. Close your laptop, they keep going." The code is open source and readable — penso/herdr-gpui, Rust on GPUI, about 6,600 lines in crates/herdr-gpui/src/teleport/ including tests. Its module doc states the same scope we arrived at independently, down to "then close the source workspace while keeping its checkout".

The UX, which we had none of

Right-click the worktree row in the sidebar → Teleport… The verb hangs off the object it acts on: no command palette, no settings page. Then a host list, each with an online dot and a subtitle — "Connected", or "Not connected; reached over SSH" — with nothing preselected, and an offline host still a legal destination.

Picking a host moves nothing. It opens a plan, and the plan is the whole design:

Teleport · feature/login from MacBook To beelink · herdr-gpui. Clones the repository there first.
Branch feature/login · 2 unpushed commits · 5 changed files, 1 untracked
beelink cannot reach GitHub, so your token is installed for pull & push. Tab 1: agent claude: resume session npm run dev: run again Tab 2: dev Shell

Three things that gets right:

  • Per-pane. Nothing is hand-waved as "your session".
  • A verb per pane — "resume session", "run again", plain "Shell" — so you know what comes back alive and what comes back as a prompt.
  • It states the remedies it will apply on your behalf, not just the inventory: it will clone the repo there, it will install a token because that host can't reach GitHub.

Then progress as named steps, each lighting up in turn:

Bundle commitsCopy changesCreate worktreeRestore changesRebuild tabsStop sourceMove sessionsStart programs

The same enum backs the errors, so a failure reads "restoring uncommitted changes failed: …" rather than a stack trace. Fifteen steps carry human labels; free diagnostics for the cost of writing the strings. Afterwards the source stays in the sidebar with a teleported mark and a teleported tab where its panes were — our two-phase commit, made legible instead of silent — and teleporting back is one step that reuses the old checkout, backed up first.

The implementation, which confirms most of our design

Dirty state becomes two throwaway commits through a temporary index — better than the git stash create I proposed, because it needs no git 2.51 and says exactly what it does: 

staged=$(git write-tree)                           # the index as it stands
cp "$(git rev-parse --git-path index)" "$t/index"  # work on a copy
GIT_INDEX_FILE="$t/index" git add -A               # + untracked, .gitignore honoured
all=$(GIT_INDEX_FILE="$t/index" git write-tree)
index=$(git commit-tree "$staged" -p HEAD -m 'staged changes')
work=$(git commit-tree "$all" -p "$index" -m 'working tree')

And the restore is four lines:

git read-tree -m -u HEAD <ref>   # working tree, binaries included
git read-tree <ref>^             # then the staged index, exactly
git update-ref -d <ref>

Bundle prerequisites from the destination's own tips answers the open question in our transport section. The destination reports up to 20,000 tips; the source excludes them, filtered through git cat-file so a ref the source never heard of can't fail the bundle. That is incremental transfer over a channel with no negotiation — precisely our "park" case.

Preflight refusals we hadn't thought of: the branch already checked out in a destination worktree, and a destination tip that isn't an ancestor of the source HEAD. Both cheap, both prevent an unrecoverable mess.

Panes are argv, not agents — the detail our design missed entirely. remap_argv re-targets each pane's command line: per-agent flag tables keep --model and its kin with their values, drop the flags naming a session or a cwd, rewrite paths under the checkout, and let an absolute program path outside it resolve on the destination's PATH. A pane doesn't restart correctly without this.

Marks keyed on (endpoint, repo, branch), never on a workspace id — "which does not survive a daemon restart". That sharpens our lineage_id: key on the durable triple rather than minting another synthetic id. And credentials, when the destination can't reach GitHub, travel over a script's stdin only — never an argument, never a log line — into a mode-600 file outside every working tree.

Where it disagrees with us, and where it's right

01

It moves the whole session, and says so

"Nothing here asks an agent to summarize: the full history moves." It reads the session file, rewrites the source checkout path inside it, and writes it where that agent looks on the destination — claude, codex, opencode, pi, omp.

That is the path-rewrite tax we deferred as "not scheduled", paid in about 500 lines. Our estimate was too pessimistic. Shipping prompt-transfer first is still right because ours is nearly free — but "expensive" is no longer the reason to defer the rest.

02

Their Claude path encoding is not ours — and upstream fixed it first

Theirs reproduces Claude Code's own encoding — every non-alphanumeric character becomes -, plus a Java-style UTF-16 hash suffix past 200 characters — with a test asserting it against Claude Code's function. Ours is replaceAll(/[/.]/g, "-"), which maps only / and .

Settled by #7825: harness-sessions/claude.ts now reproduces Claude Code's encoding exactly — non-alphanumeric units to -, a Java-hash suffix past 200 characters — and stores the path Claude itself reports on terminal_agent_bindings.transcript_path. That column is the primitive an exact cross-device resume would carry.

03

The handoff note beats both of our options

Before moving, each live agent is asked to write one:

"This work is moving to another machine. Write a handoff note to .herdr/teleport/handoff-N.md so another agent can continue seamlessly: the goal, what is done, the current state including uncommitted changes, decisions and constraints, open questions, and the exact next steps. Do not change anything else, then stop."

The note is force-added into the bundle even though .herdr is ignored, and the destination agent starts with "Read it and continue the work it describes." A fallback chain lets a different agent pick it up when the destination lacks the original.

Strictly better than 36k characters of transcript tail: an agent's own account of its intent is worth more per byte than the last N chars of what it printed, and it costs one prompt. Take this for P1, keeping terminal.transcript as the fallback for a pane whose agent is dead. The cost they accepted: a teleport waits for the slowest note, up to five minutes — which is why the review dialog says "asking agents for handoff notes" out loud.

Two constraints the matrix has to respect: a cloud sandbox refuses host workspaces.create (machineOnlyProcedure — one project, one workspace per box), so a cloud destination is created through the cloud API; and a fresh sandbox boots the released host-service, so a new procedure reaches it only with a release. The hidden-ref-on-origin transport needs nothing new on the destination, which is why it works in every direction today.

What we keep that they don't have: their transport is shell scripts over SSH by necessity. We already have the relay and an authenticated host-service on both ends, so we keep the relay-direct fetch — and we have cloud sandboxes as a destination, which has no equivalent there. The architectural lesson holds regardless: their orchestrator is a client-side driver over primitives that already existed, not a new server subsystem. Ours should be too.

Prior art

This is very solved, in pieces

Sapling Commit Cloud

THE END STATE

Every draft commit uploads as it's made — no explicit push — so another machine just sl goto <hash>. Moving machines stops being an operation at all. Our continuous mode is this, with a handoff ref standing in for a draft commit.

Jujutsu

THE CORE TRICK

The working copy is a commit; every command snapshots it. If dirty state is already a commit, transferring it is just a push. We can't adopt jj wholesale, but git stash create is the same trick in one call.

Git 2.51

OUR WIRE FORMAT

stash export / stash import is upstream shipping exactly the transfer primitive this needs.

Gitpod

ROBUST AND DUMB

Tars the workspace to object storage on stop, restores on another node. It moves node_modules too, with no dedup and no resume — necessary because a Gitpod node is ephemeral and arbitrary state must survive. We have a repo at the centre, so we move 300 KB where they move 3 GB.

Codespaces "export to branch"

THE CAUTIONARY ONE

The one-click prior art for dirty state, and its failure mode is the lesson: it needs the VM alive to bundle the work, so the moment the codespace is unreachable the uncommitted work is stranded. The forums are full of it. Argues hard for parking and for continuous handoff — the export must already have happened before you need it.

Mutagen · Syncthing

DIFFERENT PROBLEM

Excellent at keeping two live copies in sync. For a move, continuous bidirectional sync buys conflicts and syncs node_modules. Right answer if we ever want "edit on the laptop, build on the workstation".

CRIU · podman checkpoint

CONSIDERED, REJECTED

Genuinely migrates running processes, memory and all. But it wants matching kernel, arch and root, TCP connections break, and it moves a live agent's process rather than its conversation. Our sandboxes already boot fresh with no processes and relaunch agents from a session id. Restart beats migrate.

Performance

Why it feels instant, and where it won't

The file transfer is genuinely sub-second in the common case: the destination already has the project's history, so the pack holds the changed blobs and nothing else — hundreds of KB for a normal afternoon's work, one round trip of negotiation.

The long pole is bun install and friends: tens of seconds to minutes, and no protocol trick removes it. Two ways to hide it:

  • Warm standby. A plausible destination keeps a clone and its dependencies warm in the background. A move becomes fetch, checkout, resume.
  • Continuous handoff. Push the handoff ref on a debounce; the destination pre-fetches. "Move" becomes "check out the ref you already have", and the Codespaces failure mode stops existing. Costs object churn and a GC policy.

Continuous mode is where this stops being a feature and becomes the model: the workspace isn't on a device, it's on your account, and devices attach to it. Cloud sandboxes then fall out as just another destination — "move to cloud" and "move back down" are the same button.

Landmines

Traps specific to this repo

  • terminal_agent_bindings.endReason needs a moved value, or source and destination both try to auto-resume the same session.
  • A cloud workspace's name is owned by the cloud row, not the sandbox; its hostId addresses nothing; its address is a short-lived gate ticket. A move touching a sandbox goes through cloudWorkspace.*, never the generic host path.
  • projects.sparse_checkout_paths must be reapplied before restore, or the checkout "deletes" half the repo.
  • git-lfs: dirty LFS files need their objects pushed too, or the destination restores pointers.
  • Multi-repo environments mean one handoff ref per checkout, one manifest for the workspace.
  • Refuse early: a branch already checked out on the destination, or a destination tip that isn't an ancestor of the source HEAD.
  • Renderer localStorage is a shared ~10 MB quota; layout payloads must be one-shot and registered in the persisted-key registry.
  • Only if we pursue exact --resume across devices: Claude's transcript directory name and per-record cwd both encode the absolute worktree path.

Sequencing

Phasing

P0

Device picker UI and a move of committed state only, on top of the existing create-workspace-from-branch path. Ships the affordance, proves the picker, needs no new transport.

P1

The handoff commit: dirty state plus env allowlist, relay-direct transport, two-phase commit with a reclaimable source tombstone, lineage_id. Session continuity rides along in the same phase — it's a cross-host call to the existing transfer plus a moved end reason, not its own project.

P2

Park-and-resume for an offline source, continuous background handoff, warm standby destinations, cloud sandboxes as a first-class source and destination.

Not scheduled

Exact --resume across devices. Build it on evidence that the 36k-char transfer is losing people work, not before.

Unresolved

Open questions

  1. Is "move" the right verb, or is it "attach"? Continuous handoff makes the workspace device-independent, and a move becomes a UI convention over an always-synced ref.
  2. Does GitHub accept pushes to a custom top-level ref namespace, for the cheap transport?
  3. What is the size ceiling on untracked files before we refuse and ask the user to exclude?
  4. Do we ever move a running dev server's port bindings, or is "it restarted" acceptable?
  5. Per-project policy for the env allowlist: opt-in, opt-out, or a prompt on first move?
  6. Is 36k chars of context enough? Largely answered — ask the agent for a handoff note instead. What's left: should a move ever wait five minutes for that note, or write it opportunistically in the background before anyone clicks?
  7. Do we copy the review dialog's per-pane plan wholesale? It is the best idea in the reference implementation and we have no equivalent surface today.
