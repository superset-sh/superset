Machine → cloud, inside the app

The dev desktop app, screen-recorded over CDP: the workspace this very session was built in, with two live Claude panes and 95 uncommitted changes, is teleported to a brand-new cloud sandbox from the same dialog. The capture travels as a ref on origin (the sandbox clones origin anyway), the sandbox is created through the cloud API, and the restore runs as a terminal command in the sandbox. The recording ends inside the app on the destination: first the arrival terminal with the restore's own result line, then the Claude pane that resumed from the carried transcript.

One continuous Page.startScreencast of the running Electron renderer, driven by real mouse input. A screencast frame arrives only when pixels change, so the minutes the dialog spends waiting on the sandbox are a single frame; the cut holds such frames for at most five seconds. No frame was added, altered, or drawn.

The one rule that makes every row work today: the destination needs nothing new. A capture is ordinary git objects behind an ordinary ref, and any checkout that can reach origin can take it.

What in this is real

The context-menu item, the dialog, the host list, and the plan are the shipped code running in the dev app against its own host-service. The plan's counts are read by the new teleport.sourceState procedure from the checkout on disk; the destination check calls teleport.destinationState and the refusal logic behind it.

The git core underneath — capture, bundle against the destination's tips, restore, preflight refusals — is tested against real repositories, and against this monorepo's own checkout at scale:

How the cloud run was wired in a dev sandbox. This dev app runs inside a cloud workspace whose dev API cannot start sandboxes (placeholder provider credentials, localhost callback URLs). For the recording, a local façade on the dev API's port sent the five cloud procedures the dialog uses (environment.list, cloudWorkspace.create, access, list, delete) to the production API under the sandbox's own credential, and everything else to the dev API. The renderer, the dialog, the host-service publishing the ref, the sandbox, and the restore are unmodified; only the address those five calls travelled to changed. The renderer's CSP also had to admit the real sandbox domain, which a dev .env points at a local gate.

Machine → machine still needs two machines to film. Its eight-step run is exercised end to end in flow.test.ts, the real driver over the real git core across two real checkouts.
