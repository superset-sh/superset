<Callout type="warn">
The SDK is in early alpha. It is not meant for production use and may be removed in the future. Stay on the latest version (`@superset_sh/sdk@latest`) while we iterate.
</Callout>

## Client

```ts
import Superset from '@superset_sh/sdk';

const client = new Superset({
  apiKey: 'sk_live_…',
  organizationId: '…',
  // optional:
  baseURL: 'https://api.superset.sh',
  relayURL: 'https://relay.superset.sh',
  timeout: 60_000,
  maxRetries: 2,
  logLevel: 'warn', // 'off' | 'error' | 'warn' | 'info' | 'debug'
});
```

### Telemetry

The SDK reports one `sdk_method_called` event per resource call: the method name (for example `tasks.list`), SDK version, runtime, whether the call succeeded, and how long it took. Request and response data are never included. The report is sent after your call settles and is best-effort, so it cannot slow down or fail a call. Set `SUPERSET_TELEMETRY=0` to turn it off.

## tasks

### `tasks.create(body)`

Create a task.

```ts
const task = await client.tasks.create({
  title: 'Wire up auth',
  description: 'See SUPER-100',
  priority: 'high',          // 'urgent' | 'high' | 'medium' | 'low' | 'none'
  assigneeId: '<uuid>',      // optional
  statusId: '<uuid>',        // optional, defaults to first backlog status
  estimate: 4,               // optional, story points
  dueDate: '2026-12-31',     // optional, ISO date
  labels: ['bug'],           // optional
});
```

Returns a `Task`.

### `tasks.list(params?)`

List tasks with rich filters. All filters AND-combine.

```ts
const tasks = await client.tasks.list({
  assigneeMe: true,          // tasks assigned to you
  creatorMe: true,           // tasks you created
  priority: 'high',
  statusId: '<uuid>',
  assigneeId: '<uuid>',      // someone else's tasks
  search: 'auth',            // substring of title or description
  externalProjectId: '…',    // external (e.g. Linear) project id
  externalProjectName: 'Auth', // external project name, case-insensitive prefix
  externalCycleId: '…',      // external cycle id
  dueDateFrom: '2026-09-01T00:00:00Z', // due on or after (ISO 8601 with offset)
  dueDateTo: '2026-09-30T00:00:00Z',   // due on or before
  sortBy: 'dueDate',         // 'createdAt' | 'updatedAt' | 'dueDate' | 'priority'
  sortOrder: 'asc',          // 'asc' | 'desc'
  limit: 50,                 // max 500
  offset: 0,
});
```

Returns `Array<TaskListItem>`. Each row is a `Task` denormalized with `assigneeName`, `assigneeImage`, `creatorName`, `creatorImage`, and `statusName` so you don't need follow-up calls for display.

### `tasks.retrieve(idOrSlug)`

Look up a single task by id or slug.

```ts
const task = await client.tasks.retrieve('SUPER-172');
if (!task) throw new Error('not found'); // returns null when missing
```

Returns `Task | null`.

### `tasks.update(body)`

Patch a task.

```ts
const task = await client.tasks.update({
  id,
  priority: 'urgent',
  statusId: '<uuid>',
  prUrl: 'https://github.com/…',
});
```

Returns the updated `Task`.

### `tasks.delete(id)`

Soft-delete a task.

```ts
await client.tasks.delete(id);
```

### `tasks.statuses.list()`

List the task statuses (workflow states) configured for the active organization, in display order. Useful for resolving status ids before [`tasks.create`](#taskscreatebody) or [`tasks.update`](#tasksupdatebody).

```ts
const statuses = await client.tasks.statuses.list();
const todo = statuses.find((s) => s.type === 'unstarted');
```

Returns `Array<TaskStatus>`. Each entry is `{ id, name, color, type, position }`.

## workspaces

### `workspaces.list({ hostId, projectId?, projectName?, search?, tag? })`

List workspaces on a host. Workspaces are host-owned. There is no org-wide
listing; enumerate hosts with [`hosts.list()`](#hostslist) and query each one
you care about. `projectId` filters by project UUID, `projectName` by the
host-served project name (case-insensitive), `search` is a substring match on
name or branch, and `tag` keeps only workspaces carrying that tag.

```ts
const workspaces = await client.workspaces.list({ hostId: '<machineId>', tag: 'nightly' });
```

Returns `Array<Workspace>`. Rows include the host-served `projectName`
(`string | null`; null when the workspace's project row is missing on that
host, so don't assume it's always present) and `tags: string[]`.

### `workspaces.retrieve(id, { hostId })`

Look up one workspace by id on a host. Returns the same row shape as `list`
(including `worktreePath`, `worktreeExists`, `projectName`, and `tags`), or
`null` when the host has no workspace with that id.

```ts
const workspace = await client.workspaces.retrieve('<workspaceId>', { hostId: '<machineId>' });
if (!workspace) throw new Error('not found');
```

### `workspaces.create({ hostId, projectId, name, branch?, pr?, baseBranch?, skipBranchPrefix?, taskId?, agents?, command?, tags? })`

Create a worktree on a specific host. Provide exactly one of `branch` or `pr` (a pull request number; the host checks out the verified PR head and derives the branch). `baseBranch` picks the fork point when `branch` doesn't exist yet, `skipBranchPrefix` uses `branch` exactly as given instead of namespacing it under the project's branch prefix, and `taskId` links the new workspace to a task. `tags` files the workspace into a sidebar folder per tag. Optionally spawn one or more agents inside it as soon as the worktree is ready, and/or run a one-off shell `command` in the worktree. Goes through the relay tunnel: the host must be online.

Each entry in `agents` takes a preset id (e.g. `"claude"`) or a `HostAgentConfig` instance UUID: the host service resolves it against its configured rows and copies their stored `command`, `args`, and `env`. Set `effort` to override the agent's reasoning effort for that launch, or omit it to use the agent's own default. Use [`agents.list({ hostId })`](#agentslist-hostid-) to enumerate what's installed. `command` is independent of `agents`. Pass either or both.

```ts
const result = await client.workspaces.create({
  hostId: '<machineId>',     // see hosts.list()
  projectId: '<uuid>',       // see projects.list()
  name: 'wire-up-auth',
  branch: 'feat/auth',
  tags: ['auth'],            // optional: sidebar folder per tag
  agents: [                  // optional: spawn agents on creation
    { agent: 'claude', effort: 'high', prompt: 'Implement the auth flow described in SUPER-100.' },
    { agent: 'claude', prompt: 'Write integration tests for the new auth flow.' },
  ],
});

console.log(result.workspace.id);
for (const agent of result.agents) {
  if (agent.ok) console.log(agent.kind, agent.sessionId, agent.label);
  else console.error(agent.error);
}
```

Returns a `WorkspaceCreateResult`:

- `workspace`: the created workspace row (`id`, `name`, `branch`, `hostId`, `projectId`, `type`, `taskId`, …).
- `terminals`: terminals opened on the host (`{ terminalId, label? }`).
- `agents`: one entry per agent in the request (empty if `agents` was omitted). Each entry is either `{ ok: true, kind: 'terminal' | 'chat', sessionId, label }` or `{ ok: false, error }`.
- `alreadyExists`: true when a workspace for that branch already existed and was reused instead of created.

### `workspaces.createSession({ hostId, name?, agents?, command? })`

Create a project-less session workspace: a managed scratch folder with its own
git repo and no branch or PR semantics. Same `agents` and `command` sugar as
`create`. Mirrors `superset workspaces create` without `--project`.

```ts
const { workspace } = await client.workspaces.createSession({ hostId: '<machineId>', name: 'scratch' });
```

### `workspaces.update(id, params, { hostId })`

Update fields on an existing workspace on its host: `name`, `taskId` (pass `null` to unlink), and `tags` (a full replacement of the tag set; `[]` clears it). Moving a workspace to a different branch or host requires host-side orchestration and is not safe to drive directly.

```ts
await client.workspaces.update('<workspaceId>', { name: 'wire-up-auth-v2', tags: ['auth'] }, { hostId: '<machineId>' });
```

Returns the updated workspace row (`id`, `name`, `branch`, `hostId`, `projectId`, `type`, `taskId`, `tags`, …).

### `workspaces.delete(id, { hostId })`

Delete a workspace on its host.

```ts
await client.workspaces.delete('<workspaceId>', { hostId: '<machineId>' });
```

## projects

### `projects.list({ hostId })`

List projects set up on a host. Projects are host-owned; there is no
org-wide project registry.

```ts
const projects = await client.projects.list({ hostId: '<machineId>' });
```

Returns `Array<Project>` (`id`, `name`, `repoPath`, `repoUrl`, …).

### `projects.create({ hostId, name, clone?, parentDir?, import? })`

Create a project on a host. Pass exactly one of `clone` (a git remote URL,
cloned into `parentDir`) or `import` (an existing local checkout on the host).

```ts
const project = await client.projects.create({
  hostId: '<machineId>',
  name: 'superset',
  clone: 'git@github.com:acme/superset.git',
  parentDir: '/Users/me/code',
});
// or register a checkout that already exists on the host:
await client.projects.create({ hostId: '<machineId>', name: 'superset', import: '/Users/me/code/superset' });
```

Returns `{ projectId, repoPath, mainWorkspaceId, created }`; `created` is false
when the host already had a project at that path and reused it.

### `projects.setup({ hostId, projectId, parentDir? | path?, allowRelocate?, repoUrl?, name? })`

Adopt a project that already exists in the organization onto another host:
clone its repo into `parentDir`, or register an existing checkout at `path`
(`allowRelocate` permits re-importing at a different path when the project is
already set up there). A host that has never seen the project needs `repoUrl`,
and optionally `name`, so it knows what to clone.

```ts
await client.projects.setup({
  hostId: '<machineId>',
  projectId: '<uuid>',
  parentDir: '/Users/me/code',
  repoUrl: 'git@github.com:acme/superset.git',
});
```

Returns `{ repoPath, mainWorkspaceId }`.

## hosts

### `hosts.list()`

List developer machines registered in the org. Returns `Array<Host>` with `id` (machineId), `name`, `online`, `wakeCommand`, and `organizationId`.

```ts
const hosts = await client.hosts.list();
const online = hosts.filter((h) => h.online);
```

### `hosts.setWakeCommand({ hostId, wakeCommand })`

Set the shell command members run locally to wake a host (for example a
sandbox resume command), or clear it with `wakeCommand: null`. Owner-only.
Mirrors `superset hosts set-wake`; running the command is what `superset hosts wake` does on the caller's machine and has no SDK equivalent.

```ts
await client.hosts.setWakeCommand({ hostId: '<machineId>', wakeCommand: 'my-cloud resume my-box' });
await client.hosts.setWakeCommand({ hostId: '<machineId>', wakeCommand: null });
```

## agents

Terminal-agent rows configured on a specific host (the same rows shown in
Settings → Agents on that machine). Reads route through the relay tunnel:
the target host must be online.

### `agents.list({ hostId })`

List configured agents on a host in persisted display order. First call on a
fresh host seeds the bundled defaults. Returns `Array<HostAgentConfig>`.
Each row carries `id`, `presetId`, `label`, `command`, `args`, `env`, and
prompt-transport fields used to launch the agent.

```ts
const agents = await client.agents.list({ hostId: '<machineId>' });
```

### `agents.create({ hostId, workspaceId, agent, prompt?, resumeSessionId?, forkSessionId?, effort?, attachmentIds? })`

Create (launch) an agent session in an existing workspace on its host.

`agent` accepts either a preset id (e.g. `"claude"`) or a `HostAgentConfig`
instance UUID. `effort` is an agent-specific reasoning override; omit it to
use the agent's own configured default. Unsupported values fail before launch.
`prompt` is optional when restoring a previous run with `resumeSessionId`, or
cloning one into a new provider session with `forkSessionId` (pass one or the
other, not both). Returns `{ kind, sessionId, label }`.

```ts
const { sessionId } = await client.agents.create({
  hostId: '<machineId>',
  workspaceId: '<uuid>',
  agent: 'claude',
  effort: 'high',
  prompt: 'Audit the login flow for race conditions.',
});
```

## terminals

Terminal (PTY) sessions on a host, scoped to a workspace.

### `terminals.create({ hostId, workspaceId, command?, cwd? })`

Create a terminal session in an existing workspace on its host. Pass
`command` to run a one-off shell command, or omit it to open an interactive
shell. Returns `{ terminalId, status }`.

```ts
const { terminalId } = await client.terminals.create({
  hostId: '<machineId>',
  workspaceId: '<uuid>',
  command: 'bun install && bun test',
});
```

## automations

Recurring agent runs scheduled by RRULE. Requires a Pro subscription on the org for `create` / `update` / `delete`.

### `automations.list(params?)`

```ts
const automations = await client.automations.list();
// or filter by case-insensitive substring on name:
const triage = await client.automations.list({ name: 'triage' });
```

Each row is an `AutomationSummary`: the `prompt` body is omitted (it can be
large markdown). Fetch one with `automations.getPrompt(id)`. Each row includes
`scheduleText`, a human-readable rendering of the rrule.

### `automations.retrieve(id)`

```ts
const a = await client.automations.retrieve(id);
```

Returns an `AutomationSummary` (no `prompt` body: call `getPrompt(id)`).

### `automations.create(body)`

Create a recurring automation.

```ts
const a = await client.automations.create({
  name: 'Daily leads',
  prompt: 'Find new leads from Linear and update the CRM…',
  agent: 'claude', // host agent presetId, instance UUID, or 'superset' for built-in chat
  rrule: 'FREQ=DAILY;BYHOUR=6;BYMINUTE=0',
  timezone: 'America/Los_Angeles',
  v2ProjectId: '<uuid>',     // omit (with no v2WorkspaceId) for session mode
  // optional:
  v2WorkspaceId: '<uuid>',   // pin to a specific workspace
  targetHostId: '<machineId>', // pin to a specific host
  dtstart: new Date().toISOString(),
  tags: ['automation'],      // sidebar folder per tag on each run's workspace
});
```

### `automations.update(body)`

```ts
await client.automations.update({ id, rrule: 'FREQ=WEEKLY;BYDAY=MO' });
```

### `automations.delete(id)`

### `automations.run(id)`

Dispatch immediately, off-schedule. Goes through the relay to the automation's
target host. Returns identifiers for the dispatched run, not the full run row;
use [`automations.logs(id)`](#automationslogsid-params) for status.

```ts
const run = await client.automations.run(id);
console.log(run.automationId, run.runId);
```

### `automations.pause(id)` / `automations.resume(id)`

Toggle the `enabled` flag. A paused automation stops running on its schedule until you resume it.

### `automations.logs(id, params?)`

Run history. Owner-only: returns 404 if the automation isn't owned by the calling user.

```ts
const runs = await client.automations.logs(id, { limit: 20 });
```

### `automations.getPrompt(id)` / `automations.setPrompt(id, prompt)`

Read or replace the automation's prompt without going through the full update.

## pages

A page is one self-contained HTML document published to a shareable URL. Every
publish creates a new version; nothing is overwritten. Mirrors `superset pages …`.

### `pages.list({ workspaceId? })`

List pages in the organization, most recently updated first, optionally only
those published from one workspace. Returns `Array<PageSummary>` with the
latest version folded in (`latestVersion`, `sizeBytes`, `publishedAt`, `url`, …).

```ts
const pages = await client.pages.list({ workspaceId: '<uuid>' });
```

### `pages.retrieve(idOrSlug)`

Get one page's metadata by id or slug: title, visibility, `url`, `latestVersion`,
`servedVersion`, and `watch` (whether an agent session is watching it).

```ts
const page = await client.pages.retrieve('q3-pipeline-k2f9a1');
```

### `pages.versions(idOrSlug)`

List a page's versions, newest first (`version`, `label`, `sizeBytes`, `sha256`, `createdAt`).

### `pages.pull(idOrSlug, { version? })`

Resolve a version (default: the one currently served) to its metadata plus a
short-lived `downloadUrl`. Fetch that URL for the HTML body.

```ts
const pulled = await client.pages.pull('<pageId>', { version: 1 });
const html = await (await fetch(pulled.downloadUrl)).text();
```

### `pages.publish({ html, filename?, pageId?, workspaceId?, entryPath?, title?, description?, label?, visibility? })`

Publish an HTML document and get its public URL. Pass `pageId` to add a version
to an existing page; otherwise pass `workspaceId` and `entryPath` (where the page
lives relative to the workspace root), which together key the page so a later
publish with the same pair versions it instead of minting a second one.
`visibility` is `'org'` (the default for new pages) or `'just_me'`.

```ts
const page = await client.pages.publish({
  html: '<!doctype html><title>Q3 pipeline</title>…',
  workspaceId: '<uuid>',
  entryPath: 'reports/q3-pipeline.html',
  title: 'Q3 pipeline',
  label: 'first cut',
});
console.log(page.url, page.version);
```

The CLI's directory publish (assets staged next to the page) has no SDK
equivalent yet; publish a single self-contained file.

### `pages.comments.list({ pageId, activatedOnly? })`

Comment threads on a page, oldest first, each with its replies and `resolved`
state. `activatedOnly` narrows to threads a person has sent to an agent.

### `pages.comments.reply({ threadId, body, agentSessionId? })`

Post a reply into a thread. `agentSessionId` names the replying agent session
for readers; it is descriptive only.

### `pages.comments.resolve({ threadId, resolved? })`

Mark a thread resolved (the default) or reopen it with `resolved: false`.
