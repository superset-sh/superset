title: Pages

Superset Pages gives your agents a way to present designs, reports, and analysis to your team. Teammates comment directly on the page, and an agent picks up the feedback, makes changes, and publishes an updated version.

![A Superset Page presenting a cloud signup design review, with a comment pinned to the headline](/images/pages-design-review.png)

## The Design Loop

1. **Create.** Ask an agent to build a design doc, report, or proposal and publish it as a Page.
2. **Share.** Send the page's link to your team.
3. **Comment.** Teammates pin feedback to the part of the page they want to discuss.
4. **Iterate.** The agent watching the page receives new comments, updates the source, republishes, and replies to the threads it addressed.

## Create Your First Page

Open the **Pages** tab and click **Create with AI**. Superset starts an agent session that asks what you want to create, helps build the page, and publishes a link for your team. The help icon beside the **Pages** title opens this guide.

You can also ask an agent in an existing Superset workspace:

```text
Create a design doc for our onboarding flow and publish it as a Superset Page
so the team can review it and leave comments.
```

Or start with work the agent has already done:

```text
Turn your findings into a report and publish it as a Page for the team.
```

The Superset plugin includes a [Pages skill](/skills) that guides agents through building, publishing, and updating pages. A page can be a self-contained HTML file or a directory with an `index.html` and supporting assets. When an agent finishes work that someone else will read, such as a PR walkthrough, a comparison, or a report, the agent offers to publish it as a page and waits for your answer.

To publish from the CLI, run:

```bash
superset pages publish design.html --title "Onboarding design" --label "First draft"
```

The command returns a shareable URL. Publishing does not open the page or move the desktop to another workspace. See the [CLI reference](/cli/cli-reference#pages) for options.

## Find Workspace Pages

Open the Pages menu beside **Run**, above **Files / Changes / Review**. It lists pages published from the workspace, your pinned pages, and **All pages**. Choose **New page**, enter a request, and pick an agent to create it. A blue **New** indicator marks a fresh publish until you close the menu.

The main Pages list shows linked workspace names so you can see where a page came from. Clicking a page there does not switch workspaces.

Web links inside a workspace Page follow **Settings → Browser → URL links**, and links to other Pages follow **Settings → Files & Editor → Page links**. Both open outside the Page pane. If no plain-click action is set, a plain click opens a pane. Links in standalone Pages in the desktop app open in the system browser.

## Share a Page

Use **Share** to choose who can open the page:

- **Only you**: a private draft.
- **Anyone in your organization**: members of your organization. This is the default for new pages.
- **Anyone with the link**: anyone can read it without signing in. Public access does not grant comment or edit permissions, or access to the rest of the version history.

When a page is public, the **Share** button shows a globe icon.

**Shared version** controls whether the link follows the latest publish or stays on a specific version. Anonymous readers can access only that shared version.

For a new page, the CLI accepts `--visibility just_me`, `--visibility org`, or `--visibility everyone`. Republishing preserves visibility unless you explicitly change it. Shared links include the page thumbnail in link previews, including [Slack unfurls](/use-with-slack).

Anyone viewing a public page can use **Report** to flag it to the Superset team with a reason, optional details, and an optional email. The Superset team reviews reports and can take a page down, which stops its link working.

## Send Feedback Directly to an Agent

Open the page, enter comment mode, and click an element to pin feedback to it. The agent receives the comment along with context identifying the element, so teammates can point to exactly what they want changed.

On iPhone, the comments sheet keeps replies inline. Tap **Reply** to target a thread, or clear the reply target to leave a page-level comment. Resolved threads appear under the resolved-comments disclosure.

Publishing from an agent's Superset terminal attempts to register that session for new comments. Check the command's watch status; a failed registration does not fail the publish. In the workspace page pane, open the **Listening agents** menu in the page header:

- It lists every agent watching the page, including agents on other devices. Click a row to open that agent's terminal.
- The page's creator can click the **X** on a row to stop that agent watching.
- The page's creator can use **Add listening agent** to assign a running agent in the workspace, or start a new agent session and assign it.

Keep the host and agent session running for automatic feedback delivery. If the menu says **No listening agents**, the page's creator can add one. New comments are delivered when the agent is available to handle them.

The agent can change the page, answer a question in the thread, or leave feedback open when it needs more discussion. When it makes a change, it republishes the page, replies with what changed, and resolves the feedback it addressed.

## Keep Iterating on the Same Page

Publish the same source path from the same workspace to create a new version of the existing page. Your team keeps using the same link, and earlier versions remain in version history.

```bash
superset pages publish design.html --label "Simplified onboarding after team review"
```

If the source moved or you're publishing from another workspace, pass the existing page ID explicitly:

```bash
superset pages publish design.html --page <page-id> --label "Updated onboarding flow"
```

Publishing from outside a workspace works too, but there's no path for a later publish to resolve against: every run creates a separate page unless you pass `--page`. The publish tells you when that happened and prints the command to reuse.

Use the page title menu to preview earlier versions read-only, rename the page, or refresh it. You can also inspect version history or retrieve a published version:

```bash
superset pages versions <page-id-or-slug>
superset pages pull <page-id-or-slug> --version 1 > original-design.html
```

Agents connecting through MCP can publish, retrieve versions, and reply to or resolve comments with the [Pages tools](/mcp-server#pages).
