Superset and [Orchestrator](https://orchestrator.inc/) (formerly Agent Orchestrator) both manage coding agents working in separate Git worktrees. Superset centers the workspace, with terminals, diff review, connected hosts, and tools for scripting agent work. Orchestrator connects a project planning agent to workers, a live Kanban, pull requests, CI, and reviews. Its feedback loop can return a failed check, review comment, or merge conflict to the worker that owns the branch.

## At a Glance

| Requirement | Superset | Orchestrator |
|---|---|---|
| Coordinating work | Parallel workspaces and agent sessions | A project orchestrator that plans and delegates to workers, with a live Kanban |
| PR feedback | CI and review state in the workspace | CI, review, and conflict feedback routed to the owning worker |
| Review | Diff and file editor with PR context | Files and Reviews views, file editing, and reviewer-agent runs |
| Recurring work | Scheduled automations | Recurring automations with run history; reusable project Cues |
| Mobile | iPhone app for eligible Superset plans | Paired iPhone, iPad, and Android companion apps |
| Desktop | macOS; experimental Linux AppImage | macOS, Windows, and Linux |
| License | Source-available under Elastic License 2.0 | Open source under Apache-2.0 |

## What Orchestrator Brings to the Workflow

Orchestrator's project-level agent can turn a larger goal into worker tasks, pass context to each worker, and follow their progress. The board groups work by activity and PR state so the operator can see what needs attention. Supported sessions can switch between structured Chat and the agent's native terminal interface while keeping the same worktree. Orchestrator supports Claude Code, Codex, Cursor, OpenCode, and a broader [agent catalog](https://docs.orchestrator.inc/plugins/agents/).

Projects can also group a repository with its direct child repositories. With [opt-in issue intake](https://docs.orchestrator.inc/configuration/projects/), GitHub or GitLab issues can start worker sessions.

The [PR feedback loop](https://docs.orchestrator.inc/configuration/lifecycle-automation/) observes GitHub and GitLab checks and reviews. When the relevant rule is enabled, it can send actionable CI failures, requested changes, and merge conflicts back to the owning worker. The desktop also has a Files view for workspace and PR changes, file editing, a Reviews view for agent review runs, and a [session browser](https://docs.orchestrator.inc/dashboard/) that the agent can inspect and control.

Orchestrator includes a current [CLI](https://docs.orchestrator.inc/cli/) for creating and steering sessions. [Recurring automations](https://docs.orchestrator.inc/configuration/lifecycle-automation/) can start sessions from a saved prompt on a cron or RRULE schedule, and project Cues save instructions or commands for reuse. These are separate from PR feedback rules.

The [mobile companion](https://docs.orchestrator.inc/configuration/remote-access/) pairs with the desktop through an opt-in, password-protected connection. From a phone, users can follow sessions, reply to agents, handle input, and inspect PR and review state while execution stays on their computer. See [AO Mobile for iPhone and iPad](https://apps.apple.com/app/ao-mobile/id6792552173) and [AO Mobile for Android](https://play.google.com/store/apps/details?id=aoagents.dev). Remote connection options depend on the paired host and its setup.

## What Superset Brings to the Workflow

Superset runs CLI coding agents in branch-based workspaces with persistent terminals, a diff and file editor, an in-app browser, and port management. It provides a [CLI](https://docs.superset.sh/cli/getting-started), an [MCP server](https://docs.superset.sh/mcp-server), a TypeScript SDK, Slack integration, and automations around those workspaces. Connected hosts and cloud workspaces support work across devices and teams.

Superset desktop targets macOS and offers an experimental Linux AppImage. Its [iPhone app](/mobile), remote access, and automations have plan and host requirements; check [pricing](/pricing) and [remote access setup](https://docs.superset.sh/remote-access) before comparing a specific workflow.

## Try Both on the Same Task

Use the same repository, agent, model, and acceptance checks. Open the resulting diff in each app, request one change, and follow a failing CI check or review comment through to a new commit. If you work away from your desk, pair each mobile app with a running host and try replying to a worker and reviewing its PR.

## Which Should You Choose?

Choose Superset if connected hosts, team controls, or its CLI, MCP, SDK, and Slack surfaces fit the way you coordinate work. Choose Orchestrator if you want a project planning agent, worker-owned PR feedback, GitHub and GitLab support, reviewer agents, or an Apache-2.0 desktop app with iOS and Android companions. Both let you inspect changes in the app and schedule agent work. A short trial in your own repository will show which flow fits your team.

## Frequently Asked Questions

### Does Orchestrator have a CLI and scheduled automations?

Yes. The desktop uses a local daemon, and its maintained CLI can create and manage sessions, reviews, previews, and recurring automations. Schedules use cron or RRULE and run while the local host is awake and Orchestrator is running.

### Can Orchestrator review and edit files in the app?

Yes. Its Files view shows workspace and pull-request changes, and files can be edited and saved in the desktop app. The Reviews view also supports configured reviewer-agent runs.

### Can I use Orchestrator from my phone?

Yes. AO Mobile is available for [iPhone and iPad](https://apps.apple.com/app/ao-mobile/id6792552173) and [Android](https://play.google.com/store/apps/details?id=aoagents.dev). It pairs with a running desktop host; [Connect Mobile](https://docs.orchestrator.inc/configuration/remote-access/) explains local and remote connection options.

### How are the products licensed?

Orchestrator is open source under Apache-2.0. Superset's source is available under Elastic License 2.0. Read the licenses if redistribution or service hosting matters to your team.
