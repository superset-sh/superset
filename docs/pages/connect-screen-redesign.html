Why it matters more on the web

The desktop modal shows this before a first grant and skips it once anything is connected. The web screen shows it never — and the web screen is the one reached from a share link, where the person may not know what Superset is about to be allowed to do.

The same rule applies: trust copy answers “should I grant this?”, which is decided once. After that the screen is a manage view and the copy is in the way.

Open questions

  • Does the web screen get Rename? It needs the connectors.rename mutation, which exists. Cheap, and the nickname is what makes two accounts legible — so probably yes.
  • Does it share a component with desktop, or copy the shape? Desktop renders in Electron with its own design system; the web app has its own. A shared headless hook with two renderers is the honest middle, but a copy is faster and this is two screens, not twenty.
  • What does it do about the tool-call gap? Letting someone connect a second account from the web, when a second account still breaks every plugin tool call, is the same foot-gun as on the plugins page — decided separately, but it lands here too.

Not addressed here: the connect screen cannot show whether an account actually works, only that a row exists. A connection whose refresh failed is listed as needing reconnect, but one whose token is live and whose scopes are wrong looks identical to a healthy one.
