The Changes pane learns from the PR view

The v2 workspace Changes pane now renders like the PR view's Code tab — card-per-file diffs, a resizable file tree, a real toolbar — and links straight to the in-app PR view when the branch has one. Built by extracting the PR tab into shared components, not by copying it.

What shipped

Full visual & structural parity

Bordered, rounded card per file with a 16px gap; filename-first headers with the directory trailing off muted; emerald/red ± counts; always-visible collapse chevrons; a resizable in-pane file tree with ± row decorations and click-to-navigate; a toolbar with the Files pill, collapse/expand-all, prev/next comment navigation, and the unified/split toggles. Everything workspace-specific survived: section bar, inline editing, per-file actions, viewed-files, ⌘F search, scroll persistence.

A link into the in-app PR view

When the workspace's branch has a linked pull request, the pane header shows a state-tinted PR icon and #number. Clicking it opens /pull-requests/$prNumber inside the app — until now, every PR affordance in the product linked out to github.com. Hidden when there is no PR, and for session workspaces that have no project scope.

04

Found live, fixed live

Verification ran against the real app over CDP — real clicks, screenshots, and DOM measurement, using this very worktree's own 39-file diff as the test changeset. Four real bugs surfaced that code review alone would have missed; zero console errors across the whole session.

4.1Long paths painted under the ± counts

Pierre slots the filename suffix through an unstyled light-DOM wrapper div. As a flex item it defaults to min-width: auto and refuses to shrink — measured 893px inside a 513px header — so the directory text overflowed beneath the diff-stat counts. Latent in the PR tab too; its pane was just always wide enough to hide it.

slot[name='header-filename-suffix']::slotted(*) { min-width: 0 } in the shared card CSS, letting the truncate chain ellipsize.

4.2A see-through strip above sticky headers

Padding-top on the scroll container let file content show through an 8px band above every pinned card header.

Horizontal inset only on the scroller; sticky headers pin flush.

4.3Collapse-all lost a fight with the scroll hook

The scroll hook keeps its navigation target expanded while sticky tracking is armed, so collapse-all left the last-clicked file open and the toggle never flipped.

Collapsing the sticky target now releases the target in the same pane-data write.

4.4Tree state bled between pane instances

Same-kind panes render through one unkeyed component instance, so a recreated Changes pane inherited the previous pane's manual tree override — a closed pane's "show tree" choice kept the tree open in a fresh 330px pane where it should have auto-hidden.

Render-phase state reset keyed on the pane id (and biome-proof, after the linter quietly gutted the effect version).
