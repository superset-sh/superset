Why this exists

Superset derives an agent's live status entirely from hook self-report events POSTed by each agent CLI's native hooks — not from screen-scraping. That's more precise when it works, but it fails stuck rather than soft: if a hook never fires (Claude Code fires no Stop hook on a Ctrl+C/Esc interrupt), the status silently keeps its last value forever, with no way to tell "still working" from "wedged" short of reading source.

terminals explain closes that gap. It doesn't add a new detection mechanism — it exposes the evidence the existing one already has: the last hook event, when it fired, and what status that implies, so a stuck indicator is diagnosable from one CLI call instead of a source dive.

What was built

packages/host-service/src/trpc/router/terminal-agents/terminal-agents.ts

New explain procedure + explainTerminalAgentBinding(). Returns {'{'}binding: null{'}'} or {'{'}binding, derivedStatus, sinceMs{'}'}. derivedStatus is one of working / permission / failed / idle / ended — mirrors the desktop's status derivation minus "seen"-gating (the CLI has no concept of a viewed tab), plus a fifth ended status for closed terminals, which the desktop's live view hides entirely.

packages/host-service/src/terminal-agents/persistence.ts

New getTerminalAgentBindingAnyState() — live reads normally hide ended rows; explain needs them, since "the session ended, and why" is part of the answer.

packages/host-service/src/terminal-agents/index.ts

Barrel export addition for the type the router needed.

packages/cli/src/commands/terminals/explain/command.ts

superset terminals explain --workspace <id> --terminal <id> [--json]. Mirrors the existing terminals read command's conventions exactly — same workspace/host resolution, same {'{'}data, message{'}'} return shape.

packages/host-service/src/trpc/router/terminal-agents/terminal-agents.test.ts

5 new cases: no binding, live evidence + sinceMs, all event→status mappings, ended binding, cross-workspace isolation.

Where this leaves things

Two independent, complementary passes: static checks (types, tests, lint, real command wiring) confirming the code is correct in isolation, and a live run against a real claude process confirming the whole chain — hook POST → store → router → CLI formatting — behaves as designed, including a state (ended) and a failure mode (StopFailure) that only a real run could produce. The one gap left open is deliberate: this was never run against the actual production host-service backing the real desktop app, because doing that meant restarting a daemon serving 100 live workspaces without asking first.
